# Как агент принимает решения

## Пользователь и границы продукта

Аналитику нужен исполнимый план маркетинговых кампаний при ограниченных
деньгах и контактах. История относится к другой аудитории, а результаты
пилотов шумные. Поэтому агент тратит часть ресурсов на наблюдения, затем
выбирает аудитории, предложения и каналы с учётом оставшегося бюджета.

Текущий продукт выполняет этот сценарий в публичной синтетической среде:
планирование, пилоты, контроль допустимости, CSV и разбор решения.
Коммуникации с реальными клиентами, CRM и измерение реального денежного
эффекта не реализованы. Отчёт позволяет аналитически проверить решение
до использования плана, но не отправляет кампании в операционные системы.

## Решения, причины и компромиссы

| Решение | Причина | Компромисс |
|---|---|---|
| История используется как слабое предположение | В ней только клиенты, уже сменившие тариф; ID не совпадают с текущей аудиторией | Исторически редкое хорошее предложение может получить низкий приоритет |
| В начале охватываются разные ARPU-страты | Высокая выручка ячейки сама по себе не доказывает хороший отклик | Часть пилотов может расходоваться на плохие сегменты |
| Следующий пилот зависит от наблюдений | Новая информация может изменить доступный финальный выбор | Ошибочное раннее наблюдение способно повлиять на дальнейший поиск |
| Перспективные предложения измеряются повторно | Дополнительное наблюдение уменьшает модельный разброс | Повтор занимает слот, который можно было потратить на новое предложение |
| Финальная оценка уменьшена на 1,65σ | Учитывается неопределённость шумных пилотов | Штраф способен исключить выгодное, но слабо изученное предложение |
| Расходы и пилотное покрытие входят в планирование | Повторный контакт оплачивается, прирост клиента не складывается повторно | Точные ID пилотов неизвестны, покрытие оценивается приближённо |
| Допустимость проверяется отдельным модулем | Ограничения должны соблюдаться до очистки и обрезания официальным scorer | При некорректном плане агент явно отказывает |

Это сочетание методов в данном продукте. Новизна самих статистических
методов и глобальная оптимальность планировщика не заявляются.

## От истории к пилотам

[HistoricalPrior](../strategy/beliefs.py) непосредственно читает
`data/change_tariff.csv`. Для конечных неотрицательных значений до/после
перехода рассчитывается `(after - before) / max(before, 100)`, результат
ограничивается диапазоном **[−1, 2]**. Средние частично сглаживаются внутри
ARPU-сегмента с использованием пары тарифов и характеристик тарифа.
Историческая доля переходов не считается вероятностью конверсии.

`candidate_priors.csv` из [аудита данных](data_analysis.md) — отдельный
исследовательский артефакт; рабочий агент его не загружает.

Для каждого пилота [Belief.observe](../strategy/beliefs.py) приводит
наблюдение к референсному каналу и обновляет среднее/разброс с весом,
зависящим от фактического размера выборки. Публичная модель шума:
`0.804 / sqrt(n)`; дисперсия при приведении к каналу масштабируется
квадратом отношения коэффициентов.

[Agent.act](../agent.py) ранжирует следующие наблюдения по приближённой
ценности дополнительной информации, выручке ячейки, разнообразию уже
исследованных вариантов, стоимости пилота и упущенному финальному охвату.
Размер выбирается между 100 и 200 с уменьшением по аудитории и ресурсам.
Начальные действия покрывают HIGH/MID/LOW; последние доступные пилоты
могут уточнять перспективные предложения. Это последовательная
эвристика, не точное решение всей задачи планирования эксперимента.

На платную разведку выделяется до 18% начального бюджета, не более 18 000 у.е.;
после исчерпания этой части возможен бесплатный канал. Резервируется часть
контактов для финала. Бесплатный контакт тоже расходует охват и может дать
отрицательный эффект.

## Финальный портфель

[make_options](../strategy/portfolio.py) допускает только предложения,
которые действительно прошли пилот. Для каждой ячейки берётся лучший
исследованный target по оценке `mean - 1.65 * std`, затем рассматриваются
целая ячейка и срезы по потреблению данных/звонков размером до 5 000.

Каналы сравниваются после вычета стоимости финальных контактов. Для
положительного консервативного эффекта коэффициент выше единицы ограничен
единицей из-за возможного насыщения; для отрицательного используется полный
коэффициент. Пересечение с пилотами оценивается вероятностно по размерам
выборок и последним средним всех исследованных предложений в той же ячейке.
Финальные аудитории не пересекаются между собой.

Планировщик перебирает цены ограниченных ресурсов и улучшает комбинацию
заменами кампаний. Если все оценки неположительны, выбирается одна допустимая
исследованная кампания с наилучшей модельной оценкой после поправки на риск.
Это может оставаться убыточным. Оценка относится к дополнительному финальному
эффекту, не ко всему фактическому net пилотов и финала.

[validate_plan](../validation/plan.py) проверяет схему, тарифы и каналы,
размеры аудиторий, бюджет и контакты. Сам валидатор сообщает пересечения
как предупреждения; Agent дополнительно отклоняет любой пересекающийся
финальный план. Полосы `μ ± σ` и штраф `1.65σ` не являются подтверждённым
доверительным интервалом или гарантией доходности.

## Доказательства и слабые места

[Карта измерений](evidence.md) связывает поведение с исходными JSON/CSV и
версиями кода. Сравнение с фиксированным расписанием отделяет влияние
адаптации от финального планировщика: в `mixed_2` адаптация помогла,
в `rare_1` фиксированный вариант лучше. Общего превосходства не доказано.

Часть прибыльных предложений может остаться неисследованной. При ограничении
20 пилотов это существенный риск, особенно при плохом историческом приоритете
редкой комбинации. Пилотные ID неизвестны, приближение покрытия не точное.
Статистические предположения могут не соответствовать другой модели эффектов.
Профили без текущего тарифа/ARPU не входят в исследуемые ячейки; невалидный
baseline имеет нулевую плановую ценность, но строки расходуют контакты.

## Дальнейшее развитие

Следующие пункты — план, **не реализованные возможности**:

| Направление | Следующий проверяемый результат |
|---|---|
| Обнаружение редких выгодных предложений | Сравнение одной заранее заданной политики с текущей по найденным предложениям, общему net и нижнему хвосту на новых моделях, а не только новых seed |
| Калибровка неопределённости | Проверка покрытия прогнозов и ошибок выбора на независимых сценариях; отдельная оценка цены консервативного штрафа |
| Реальное применение | Адаптер разрешённых данных и контролируемых пилотов, ограничение частоты контактов, контроль доступа и подтверждение отправки аналитиком |
| Мониторинг поведения | Сопоставление прогноза и результата после запуска, обнаружение изменения распределения отклика |

Добавление более сложного метода оценивается по поведению системы:
качество выбора, соблюдение лимитов, воспроизводимость и стоимость исполнения.
Текущий локальный прототип не требует внешнего API.

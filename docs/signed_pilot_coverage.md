# Добавочный эффект финальных кампаний после знаковых пилотов

## Решение и происхождение результатов

**KEEP BASELINE — оставить production без изменений.** Формула кандидата корректно описывает добавочный эффект при принятом приближении покрытия; эмпирический результат смешанный. Улучшения на отрицательных моделях не отменяют отдельные проигрыши и ухудшения распределений. Консервативный протокол при таком результате не рекомендует перенос перед сдачей.

## Что исправляет единственный кандидат

Официальный scorer выбирает максимальный эффект для каждого контактированного клиента среди пилотов и финальных кампаний, включая отрицательные значения. Поэтому для ранее не контактированного клиента добавка равна `r`, а после лучшего предыдущего эффекта `s` — `max(s,r)-s = max(0,r-s)`. Старое обрезание пилотных оценок снизу нулём теряло восстановление части отрицательного эффекта.

Для всех пилотов той же ячейки «текущий тариф × ARPU», включая другие целевые тарифы, берётся **последняя posterior mean исследованной гипотезы**, умноженная на коэффициент канала пилота относительно reference. Знак `s_i` сохраняется. При неизвестных ID используется прежнее приближение независимой равномерной выборки:

```text
q_i = min(1, n_i / N)
s_i отсортированы по убыванию
w_i = q_i * произведение(1-q_j), j<i
p0 = произведение(1-q_i)
increment(r) = p0*r + сумма w_i*max(0,r-s_i)
```

Пример: `s = −0,20`, покрытие `q = 0,50`, финальная оценка `r = −0,05`. У половины клиентов восстановление равно `+0,15`, у остальных новый эффект `−0,05`: добавка `0,5×0,15 + 0,5×(−0,05) = +0,05`. Старый расчёт дал бы `−0,05`. При сумме базовой ценности аудитории 1 000 это **+50 вместо −50 у.е. до полной стоимости финальных контактов**. Это расчётный пример, а не измеренный net.

Одна формула применяется к средней и риск-скорректированной оценкам. Полная стоимость финального контакта вычитается; риск **1,65**, масштабы каналов, пилотная политика, priors/posteriors, аудитории и поиск портфеля сохранены. В изолированном Agent изменены только импорт portfolio и путь к **корневому** `data/change_tariff.csv`. Во всех 360 трассах реально использована история из **14 822 валидных переходов**, fallback-prior не включался.

Это приближение по неизвестному пересечению выборок и шумным оценкам. Оно не получает истинные эффекты или ID пилотов, не является oracle и не гарантирует улучшение фактического net. Модели импортируются только существующим измерительным harness, не кандидатом.

## Заранее зафиксированные критерии и решение

1. **PASS:** нет ошибок, таймаутов, невалидных планов, dropped/capped и нарушений лимитов в основных попытках.
2. **PASS:** пилоты и потраченные на них ресурсы совпадают во всех парах; исторический prior действительно загружен.
3. **PASS:** положительная медиана попарного изменения минимум на двух stress-моделях, включая преимущественно отрицательную, получена в обеих фазах.
4. **PASS:** в обеих фазах защищённые `mock`, `devin_mixed`, `mixed_1`, `mixed_2` не потеряли median, q10 или число корректных положительных запусков.
5. **Осторожное решение — KEEP BASELINE:** обнаружены пять ухудшений сводных метрик и десять проигранных пар. В holdout у `devin_unlucky_noisy_pilots` снизились q10 и минимум; потерь положительных запусков нет. Это смешанный результат по заранее указанному консервативному правилу.

- **development:** положительная медиана попарного изменения на 5 stress-моделях: devin_all_bad, negative_1, negative_2, rare_1, rare_2. Защищённые модели `mock`, `devin_mixed`, `mixed_1`, `mixed_2`: PASS, median/q10/число положительных не снизились.

- **holdout:** положительная медиана попарного изменения на 4 stress-моделях: devin_all_bad, negative_2, rare_1, rare_2. Защищённые модели `mock`, `devin_mixed`, `mixed_1`, `mixed_2`: PASS, median/q10/число положительных не снизились.

Условие положительной медианы минимум на двух stress-моделях, включая преимущественно отрицательную, оценивается отдельно от остальных критериев. Наличие такого выигрыша и прохождение защищённых моделей не разрешают скрывать проигрыши остальных моделей. В development, например, медиана `rare_2` ухудшилась с **−282 807,68 до −289 669,67**, хотя медиана попарного изменения положительна **+4,71**; это разные статистики. Медиана `devin_unlucky_noisy_pilots` тоже снизилась.

По финальному консервативному правилу протокола смешанный результат означает **KEEP BASELINE**. Математическое исправление сохраняется как изолированное исследование; перенос в production и main сейчас **не рекомендован**. Это инженерное решение в условиях дедлайна, не тест статистической значимости и не доказательство превосходства или проигрыша на скрытой среде.

## Воспроизведение

Из корня clone ветки `codex/signed-pilot-coverage`, Python 3.12; для точного кандидата можно checkout commit `1f659e1ece2e0ef00243acdb0b0d1ae15c049216`. Не запускайте построение нового кандидата или перезапись freeze перед воспроизведением уже опубликованного эксперимента.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q experiments/signed_pilot_coverage/test_formula.py
.venv\Scripts\python.exe experiments/signed_pilot_coverage/measure.py --phase development --out reports/signed_pilot_coverage/development_rerun.json
.venv\Scripts\python.exe experiments/signed_pilot_coverage/measure.py --phase holdout --out reports/signed_pilot_coverage/holdout_rerun.json
.venv\Scripts\python.exe experiments/signed_pilot_coverage/crosscheck.py --out-dir reports/signed_pilot_coverage/crosscheck_rerun
```

Имена `*_rerun` должны быть новыми: инструменты намеренно отказываются перезаписывать прежние попытки. Повторение не должно менять корневой `submission.csv` или `reports/decision_trace.json`. Все результаты относятся к указанным SHA и известным синтетическим моделям; реальные клиенты, скрытое судейство и перенос на другую эффект-модель здесь не проверены.

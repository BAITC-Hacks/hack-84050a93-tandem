# Разделение работы

## Участник 1 + Codex: основное решение и интеграция

Владеет `agent.py`, `strategy/`, `README.md`, `requirements.txt`,
`submission.csv`, `tools/run_baseline.py`, корневыми настройками и интеграцией.
Отвечает за выбор пилотов, оценки эффекта, выбор кампаний и финальную сдачу.

## Участник 2: анализ и объяснение результата

Владеет `analysis/`, `tools/analyze_data.py`, `docs/data_analysis.md`,
`docs/demo.md`, `reports/data_audit.json`, `reports/candidate_priors.csv`.
Проверяет результаты Devin и составляет понятный сценарий демонстрации.
Первый собственный результат: воспроизводимый аудит качества данных.

## Devin под управлением участника 2

Владеет `validation/`, `tools/benchmark.py`, `tests/`, `docs/validation.md`,
`reports/benchmark*.json` и `reports/benchmark*.csv`.
Отвечает за независимую проверку ограничений, воспроизводимости и сравнение
исходного шаблона с агентом команды. Если `agent.py` ещё отсутствует, работает
с официальным шаблоном и маленькими искусственными примерами.

## Общие правила

- Официальный пакет и его CSV не менять; необходимые преобразования делать в памяти.
- Для новой зависимости предложить изменение участнику 1; не менять requirements параллельно.
- Участник 2: ветка `codex/data-audit`; Devin: `codex/validation`.
- Обе ветки внутри https://github.com/BAITC-Hacks/hack-84050a93-tandem.
- Никаких force push, переписывания истории или подмены автора.
- Маленькие законченные коммиты; передавать SHA, список файлов и команды проверки.
- Финальную интеграцию в main делает участник 1; Devin не сливает сам.
- Нельзя требовать готовности соседнего модуля для первого результата.

## Контракт агента

`from agent import Agent`; `Agent().act(env) -> list[dict]`.
Разрешены публичные `env.customer_profile`, `env.tariffs`, `env.channels`,
остатки ресурсов, `env.pilot_history`, `env.run_pilot`.
Запрещено получать скрытые эффекты через замыкания, introspection, gc или
организаторские файлы. Экспериментальный harness может создавать отдельные
синтетические среды, но не передавать модели эффектов агенту.

## Контракт валидатора

`validate_plan(campaigns, profile, tariffs, channels, remaining_budget,
remaining_contacts) -> dict` в `validation/plan.py`.
Выход: `valid: bool`, `errors: list[str]`, `warnings: list[str]`,
`total_contacts: int`, `total_cost: float`, `unique_customers: int`,
`campaigns: list[dict]` с размером сегмента и стоимостью.
Входные DataFrame и список кампаний не изменяются.

Это preflight после пилотов: remaining_* берутся из публичной среды.
Возвращать ошибки для неизвестных тарифов/каналов/фильтров, 0 или >10 кампаний,
пустых сегментов, нечисловых/нефинитных остатков и превышения доступных ресурсов.
Считаем полный размер запрошенного сегмента и отклоняем >5 000: официальное
обрезание допускается скорером, но нашей стратегии на него полагаться не следует.
В отчёте явно различать число контактов и число уникальных людей.
Оценить пересечения с конкретными ID пилотов через публичный интерфейс нельзя;
не запрашивать скрытый список pilot IDs.

## Контракт benchmark

`python tools/benchmark.py --agent agent:Agent --seeds 0:10 --out reports/benchmark.json`.
`--seeds 0:10` означает seed 0..9. Шаблон: `--agent agent_template:Agent`.
Использовать официальный evaluate_agent; измерять время, net, контакты,
расходы, пилоты, число финальных кампаний, исключения и отбрасывания.
При отсутствии agent.py сообщить это явно, не выдавать шаблон за наш агент.
В отчёте фиксировать SHA Git, dirty flag, версии зависимостей и список seed.
Проверять воспроизводимость submission дважды с seed 42. Ошибка/таймаут
не должны теряться из знаменателя числа прогонов.

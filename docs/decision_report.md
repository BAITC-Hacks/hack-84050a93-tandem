# Интерактивный разбор плана

`reports/decision_report.html` — автономный отчёт для аналитика по сохранённому
запуску seed 42. HTML содержит стили, JavaScript, исходный CSV и журнал JSON;
внешних библиотек, шрифтов и сетевых запросов нет. Он показывает план,
не запускает маркетинговые кампании и не изменяет стратегию агента.

Скачайте HTML и откройте его в обычном браузере. GitHub показывает исходный
код HTML, поэтому для интерактивного просмотра нужен локальный файл.

## Сценарий просмотра

1. **План кампаний:** общий расход с пилотами и три финальные кампании.
   Нажмите «Разобрать решение» у нужной кампании.
2. **Основания решения:** прямые пилоты предложения, наблюдения и плановые
   оценки. Для `tandem_03` показаны пилоты №5 и №19.
   Таблица «Если заменить только канал» сравнивает четыре канала для той же
   аудитории: цену, консервативную оценку, разницу с выбранным каналом и
   расход всего плана вместе с пилотами. Недопустимый бюджет выделен отдельно.
3. **Пилоты:** переход из карточки фильтрует журнал по предложению.
   Можно дополнительно выбрать ARPU-сегмент или вернуть все наблюдения.
4. **Проверяемость:** сохранённый preflight, версии, контрольные суммы,
   скачивание исходных CSV/JSON. Скачанные файлы используют LF и соответствуют
   указанным контрольным суммам.

Контакты вместе с пилотами — не число уникальных клиентов. Оценка эффекта
кампании уже учитывает её стоимость и приблизительное пересечение с пилотами,
но не включает полный результат пилотов. Она не является измеренной прибылью
или прогнозом скрытого судейства. Полосы в журнале показывают модельные
`μ ± σ` в масштабе референсного канала, не доверительный интервал.

## Обновление отчёта

### Выполнить агента и получить новый результат

После установки зависимостей из README выполните:

```powershell
.venv\Scripts\python.exe tools/run_demo.py
```

Linux/macOS: `.venv/bin/python tools/run_demo.py`.

Команда создаёт новую папку в `reports/demo_runs/`, выполняет официальный
экспорт с двумя seed-42 прогонами, затем строит отчёт по свежим CSV/JSON.
Предварительно сохранённые `submission.csv`, `reports/decision_trace.json`
и `reports/decision_report.html` этому сценарию не нужны и не заменяются.
В конце печатается путь к новому HTML для открытия в обычном браузере.
Браузер автоматически не запускается.

В папке запуска остаются `run_status.json` и stdout/stderr каждого этапа.
Успех — статус `complete` и код выхода 0. Статусы `failed` и `cancelled`
не считаются готовым результатом, даже если часть файлов уже создана.
Контрольные суммы исходников и данных сверяются до и после выполнения;
если они изменились в процессе, запуск помечается неуспешным.

`--timeout` задаёт общий лимит времени обоих этапов (по умолчанию 300 секунд,
не более 300). `--output-root` задаёт родительскую папку новых запусков;
внутри проекта разрешены только пути в `reports/`. Имя каждого запуска
выделяется эксклюзивно, в том числе при одновременных запусках.
Существующие папки отдельных запусков не переиспользуются.

### Перерисовать сохранённый результат

Генератор использует только стандартную библиотеку Python. Из корня проекта:

```powershell
# Windows, после установки окружения по README:
.venv\Scripts\python.exe tools/render_decision_report.py
```

Linux/macOS: `.venv/bin/python tools/render_decision_report.py`.

После изменения алгоритма сначала обновите `submission.csv` и журнал через
`tools/export_strategy.py`, выполните `tools/verify_submission.py`, затем
создайте новый HTML. Генератор отчёта сам агента не запускает.

Можно указать `--trace`, `--submission`, `--out`. Выходной файл должен иметь
расширение `.html`; внутри репозитория разрешена только директория `reports/`.
Входные файлы защищены от перезаписи, новый HTML заменяет старый атомарно.

До записи генератор проверяет:

- полный набор и SHA-256 исходников/данных стандартного экспортера;
- SHA-256 CSV, заголовок и точное совпадение строк с финальными кампаниями;
- согласованность сохранённого preflight, размеров аудиторий и затрат;
- расходы и контакты вместе с пилотами, лимиты кампаний и пилотов;
- seed 42 и отметку совпадения двух экспортов в журнале;
- конечность чисел, типы полей и отсутствие повторных ключей JSON.

Для сравнения каналов дополнительно пересчитываются аудитории выбранных
кампаний по профилю с проверенным хешем, их непересечение и сохранённые
числовые оценки. Повторный запуск самого агента выполняет отдельная команда
`tools/verify_submission.py`.

## Как сравниваются каналы

`tools/channel_explanations.py` читает публичный профиль и последние
сохранённые posterior каждой исследованной гипотезы. Для каждой финальной
кампании он повторяет расчёт из `strategy/portfolio.py`: масштабирование
по публичному коэффициенту канала, поправку `1.65 * std`, приближённое
вычитание уже полученного эффекта пилотов и стоимость финальных контактов.
Для покрытия используются все пилоты в той же ячейке тарифа/ARPU, включая
другие целевые тарифы. Точные ID участников пилотов не читаются.

Меняется только канал одной кампании. Аудитория, целевой тариф, прошедшие
пилоты и остальные кампании фиксированы. Поэтому разница оценок — модельное
следствие одной замены; она не описывает повторную оптимизацию портфеля,
фактическую прибыль или причинный эффект. Превосходство выбранного канала
в этой таблице не доказывает его превосходство в скрытой среде.
Коэффициент выше единицы для положительных оценок ограничен единицей из-за
возможного насыщения. Для отрицательной консервативной оценки используется
полный коэффициент канала — как в действующем планировщике.

До показа альтернатив генератор требует воспроизведения выбранного канала:
аудитории, стоимости, средней и консервативной оценки, масштабированных
mean/std. Допуск для чисел — `rel_tol=1e-10`, `abs_tol=1e-6`.
Несогласованность прерывает генерацию. Адаптер закреплён на хешах текущих
`agent.py`, `strategy/portfolio.py` и `mock_environment.py`: после изменения
их семантики нужно пересмотреть адаптер, а не просто обновить журнал.
Внутри HTML остаются только агрегаты, строки клиентов туда не добавляются.

Полный демо-сценарий на коммите `80cef96` завершился за 2,875 секунды:
свежий CSV совпал с артефактом сдачи, все три выбранных набора оценок
воспроизведены, исходные CSV/JSON остались неизменными. Числа всех 12
вариантов и хеши сохранены в
[`reports/channel_explanation_check.json`](../reports/channel_explanation_check.json).
Это локальное выполнение и сверка чисел. Проверка взаимодействия с новой
таблицей в браузере вторым участником остаётся отдельным шагом.

## Реализация и просмотр

- `tools/render_decision_report.py` — проверка входов и генерация.
- `tools/channel_explanations.py` — проверяемое сравнение каналов по сохранённым наблюдениям.
- `tools/run_demo.py` — новый полный запуск и диагностика его этапов.
- `reporting/decision_report.template.html` — интерфейс без зависимостей.
- `reports/decision_report.html` — готовый артефакт.

Динамические подписи вставляются через `textContent`; встроенный JSON
экранирует символы, способные закрыть тег `script`. CSP запрещает сетевые
ресурсы. Вкладки работают с клавиатуры, таблица пилотов прокручивается на
узком экране. Отрицательная оценка и вынужденный выбор убыточного варианта
выделяются отдельно.

При разработке отчёт открыт через локальный HTTP-предпросмотр: проверены
выбор третьей кампании, связь с пилотами №5/№19, пустой результат фильтра
и раздел происхождения данных; ошибок в консоли не обнаружено. Прямой
просмотр `file://` инструмент автоматизации блокирует, поэтому этим
инструментом он не подтверждён.

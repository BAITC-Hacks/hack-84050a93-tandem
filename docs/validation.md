# Независимая валидация и benchmark

## Preflight финального плана

Публичная функция:

```python
from validation.plan import validate_plan

report = validate_plan(
    campaigns,
    env.customer_profile,
    env.tariffs,
    env.channels,
    env.remaining_budget,
    env.remaining_contacts,
)
```

В `report` возвращаются `valid`, списки `errors` и `warnings`, полный расход контактов и денег, число уникальных клиентов и детали каждой кампании (`segment_size`, `cost_per_contact`, `cost`, пересечение с предыдущими кампаниями).

Валидатор строже официального скорера: он отклоняет пустой план, неизвестные тарифы/каналы/значения фильтров, пустые сегменты, сегмент больше 5 000 и план, который превышает остаток бюджета или контактов. Скорер умеет обрезать часть таких кампаний, но стратегия команды не должна зависеть от неявного обрезания. Пересечения — предупреждение: повторные контакты оплачиваются и расходуют охват, а клиент учитывается один раз. `push` имеет нулевую цену, но его контакты учитываются.

Функция не изменяет список кампаний, профиль, справочник тарифов или каналов. Она не пытается определить пересечение с pilot IDs: публичная среда их агенту не раскрывает.

Тесты используют только маленькие синтетические DataFrame и не требуют API:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## Воспроизводимый benchmark

Шаблон организатора:

```bash
python tools/benchmark.py \
  --agent agent_template:Agent \
  --seeds 0:10 \
  --out reports/benchmark_template.json
```

Текущий агент команды:

```bash
python tools/benchmark.py \
  --agent agent:Agent \
  --seeds 0:10 \
  --out reports/benchmark_agent.json
```

`0:10` означает seed 0–9. Для каждого прогона инструмент запускает официальный `local_eval.evaluate_agent` в отдельном процессе и сохраняет seed, net, расходы, контакты, уникальный охват, количество пилотов и финальных кампаний, время, исключение, timeout и число отброшенных скорером кампаний. `--timeout` по умолчанию равен 300 секундам на прогон. Ошибки и timeout остаются в знаменателе `runs` и `positive_rate_all_runs`.

Рядом с JSON создаётся CSV с каждой попыткой. В метаданных JSON сохраняются SHA, dirty flag, `git status --porcelain`, версии Python/pandas/numpy и точный список seed. Два независимых запуска формирования submission с seed 42 проверяют детерминированность.

Числа относятся только к публичной mock-модели. Они проверяют механику и устойчивость, но не предсказывают эффект на скрытой модели или место команды.

## Дополнения после независимого ревью

- Preflight вызывается до очистки кампаний официальным evaluator. Пустой,
  недопустимый или обрезанный план имеет статус `invalid_plan`, даже если
  пилоты дали положительный net. `valid_positive_runs` считает только корректные
  положительные запуски; `positive_runs` отдельно отражает знак доступного score.
- Для каждого запуска сохраняются `preflight_valid`, `preflight_errors` и
  `capped_campaigns`. Повторяемость CSV не подменяет проверку допустимости.
- Дочерний процесс читает данные из корня репозитория. Родитель получает
  отчёт до ожидания завершения процесса, чтобы большой вывод не заблокировал
  очередь. Таймаут проверяется отдельно.
- Валидатор отклоняет неизвестные поля (включая `explicit_ids` в финальном плане),
  некорректные типы, дробный остаток контактов и повторяющиеся ID профиля.
- Исторические `benchmark_agent.json` и `benchmark_template.json` сохранены
  как исходные результаты Devin; повторная проверка отражается в отдельных
  `benchmark_review_*.json`, с собственными SHA и версиями среды.

## Синтетические stress-сценарии

Отдельный harness создаёт собственные профили и модели эффекта внутри замыкания `make_environment`; агент получает только публичный интерфейс:

```bash
python tools/stress_benchmark.py --agent agent:Agent --seeds 0:5 \
  --out reports/benchmark_stress.json
```

Сценарии явно помечены как искусственные: все эффекты отрицательны; смесь хороших и плохих; редкий хороший сегмент; слабый сигнал с неудачными шумными пилотами; малые, пропущенные и пустые ячейки. Они не имитируют и не раскрывают скрытые тесты организатора.

На зафиксированном запуске текущий агент соблюдал preflight во всех 25 попытках. Он был положительным 5/5 в mixed, low-signal noisy и small/empty сценариях, отрицательным 5/5 при всех плохих эффектах и 5/5 пропустил редкий хороший сегмент. Последнее — обнаруженное ограничение exploration: хороший сегмент из 12 клиентов не компенсировал потери на остальных контактах. Результат сохраняется, а не исключается из отчёта.
